# Independent release procedure

The product entry is margin-reader from the local marginreader npm package. The name is provisional and registry ownership has not been checked. Version 0.9.4 and the public runtime contract are preserved; the optional AgentsCompany manifest is compatibility metadata, not a host requirement.

1. Run npm run test:release. It snapshots only project source/config/tests into a temporary directory and runs check and npm test there. Review every failure/skip and legacy host preflight result.
2. Run npm run test:package. This invokes release:pack unless an exact tarball is supplied as an argument.
3. scripts/release-pack.cjs copies controlled inputs to a temporary source directory, regenerates contracts/docs there, obtains PDF.js/KaTeX assets from pinned installed dependencies, syntax-checks, npm packs, unpacks and verifies the payload. The committed lock is copied to a release-only npm-shrinkwrap.json, preserving transitive versions and platform selectors while npm installs the appropriate native packages. Asset-source package versions must match pinned dependencies. No working-source generator runs and no node_modules is copied into the tarball.
4. scripts/verify-package.cjs installs that tarball via npm into a new consumer directory with an empty user config and temporary HOME. No NODE_PATH or host variables are inherited. npm chooses target-platform native optional dependencies. Install logs are retained.
5. The installed bin is executed from the consumer cwd. On macOS the workflow runs in sandbox-exec with deny network*, including descendants; an actual outbound TCP probe must fail EPERM before business checks. This proves process-level network denial on the recorded platform, not a universal native-code audit. Optional serve assets are checked separately using loopback outside this sandbox.
6. Review filelist.json, SHA256SUMS, npm-pack.json, package-verification.json and offline-workflow.json under its verify-TIMESTAMP directory. Review overall and scope, not just exit status. Reports distinguish applicableSourceStatus/packageStatus from overall; required legacy gates blocked make the aggregate partial even if all applicable package/source checks pass. A failed/blocked verification is not a deliverable approval.

Output is artifacts/cli-product-20261018/release/run-TIMESTAMP/. Each run is new; earlier artifacts are retained. To verify an existing exact archive: node scripts/verify-package.cjs /absolute/file.tgz. Test temporary directories are removed, but logs and reports survive in a new verify-TIMESTAMP directory for every verification attempt.

The files allowlist admits runtime, typed CLI, TUI, terminal-visuals, curated docs, MIT/notices and browser source plus freshly generated vendor assets for optional serve. It excludes development tests/scripts, package-lock (replaced by the generated npm-shrinkwrap), node_modules, source-location.json, workspaces, credentials, artifacts, dist-plugin and private historical records. Generated vendor is a redistribution asset, never copied from the working ui/vendor directory. npm install does not trigger a prepare/build lifecycle.

The optional build:plugin path remains separate. It includes tui/terminal-visuals and copies current-machine dependencies for a compatible host platform. It must not be labeled a cross-platform npm distribution. It can write generated source files and should be invoked only in an isolated copy during release work. Never install over a running user application in this procedure.

Platform matrix must distinguish Node engine declaration from actual tests. Validate minimum Node, supported LTS versions, macOS arm64/x64, Windows x64 and Linux x64 before advertising each. Native canvas/FSRS, CJK fonts, RTF, voice/dictionary and FFmpeg capability differences remain documented. Fully offline installation would need separately designed platform archives or a verified dependency cache; this tarball does not promise it.
