# Mini Notion 1.25.0 — 启动、媒体与文件编辑改进

日期：2026-10-17。改动继续使用现有 Electron 桌面、React 界面、单写入后端和原有目录工作区格式；没有引入新的运行时依赖。

## 启动路径

- 将文档编辑器、数据库、原始文件查看器、图标全目录和图片/emoji 选择器拆成按需加载的界面。只读数学预览独立于完整编辑器，避免反向依赖重新把编辑器带入入口。
- `dist/startup-report.json` 记录入口的全部静态依赖，而不只统计入口文件。构建会拒绝完整编辑器、Agent 面板或选择器重新进入该静态依赖图。
- 原生页面启动时，从已有的小型 manifest 和当前页缓存读取一个加载提示，提前并行请求 PageView 和 Editor。提示只决定加载哪些代码；实际可编辑数据仍由后端校验并提供。不存在或过期的提示不会阻止工作区加载。
- 已完成预载的组件同步挂载，避免重新经过 React.lazy 的等待状态。组件引用在每次页面挂载期间保持稳定，普通保存和封面更新不会因此重建编辑器。
- 历史日志改为第一次历史操作或实际编辑时读取。读取前不会迁移历史文件；实际编辑先检查日志格式和对象校验，再发布工作区。日志损坏会阻止该次编辑并保留原文件，修复后可以重试。
- 目录事务发布时若重定位普通文件，历史补丁包含最终的文件路径，供撤销和重做使用。

## 界面与图片

- 首页先呈现 60 个页面，继续显示按钮按批增加；CSV 先呈现 200 行。完整数据仍参与业务操作，打印不做上述截断。
- 封面、卡片和图库共用图片显示组件，使用原生延迟加载、异步解码和稳定的容器尺寸。主页面封面优先加载；加载失败有明确提示和重试入口。
- 上传、粘贴及拖放图片先验证可解码性；验证成功后保存原始文件字节，保留 GIF/SVG 等原文件格式。失败不会覆盖当前封面。链接预览有错误和超时反馈。
- 封面位置支持指针调整与键盘调整：方向键每次 2%，Shift 加方向键每次 10%，Enter 保存，Escape 退出。
- 工作区文件图片提供原始尺寸、25%–300% 缩放、适应窗口、尺寸提示和错误重试；沿用现有明暗主题。
- 错误通知使用错误图标、颜色和 alert 语义，避免将失败显示为成功。

## 文件编辑与保存

原始文本文件的恢复草稿由串行写入器合并，180 毫秒内的重复输入保留最新值；持续输入也定期留下恢复点。失焦、离开页面和关闭窗口都会等待待写草稿。旧的慢写入先完成，新的草稿或清除操作随后执行，避免旧内容晚到后覆盖新内容。

保存文件继续使用原有 hash 冲突检查。关闭窗口的 IPC 回执会等待所有已注册编辑器完成，任一编辑器保存失败都会返回失败，窗口不会因其他编辑器先完成就提前确认保存。

PDF 导出会等待延迟界面、图标、字体和图片；页面内容加载超时则报告失败，避免生成只有标题的 PDF。

## 测量方法与解释边界

`scripts/profile-startup.mjs` 在隔离工作区副本中启动完整 Electron 进程。报告分别记录进程/窗口、侧栏、实际 contenteditable 编辑器和两帧绘制时间；验证活动页一致、焦点能够进入编辑器且可接收键盘导航。MutationObserver 记录真正的 DOM 出现时刻，避免把 Playwright 轮询间隔算成应用耗时。

后端分解脚本 `scripts/profile-startup-breakdown.mjs` 记录构造、存储加载、扫描及文件读取/JSON 操作的次数和耗时，只输出汇总信息。基准使用真实 771 页工作区的 APFS 隔离副本或自动生成的测试数据，没有在用户笔记上执行写入测试。

最终比较在同一台 Mac、没有并行构建干扰时进行，先运行旧安装版三个新进程，再运行最终生产构建三个新进程：

| 指标 | 旧安装版 1.24.9 | 新生产构建 1.25.0 |
| --- | --- | --- |
| 编辑器实际出现后的两帧绘制，三次样本 | 1,201 / 1,032 / 1,020 ms | 942 / 1,010 / 954 ms |
| 上述 DOM/绘制指标的样本中位数 | 1,032 ms | 954 ms |
| 自动化完成焦点/键盘验证，三次样本 | 2,044 / 1,158 / 1,127 ms | 1,122 / 1,126 / 1,111 ms |
| 活动页编辑器内容 | 24 个匹配块，可输入 | 24 个匹配块，可输入 |
| 页面脚本异常 | 0 | 0 |

旧版首轮的 2,044 ms 是自动化完成时间；同一轮编辑器绘制已经在 1,201 ms 完成，不能把它解释成真实两秒空白启动。更合适的结论是：本组有限样本中，实际编辑器绘制约 1 秒，可输入验证约 1.1 秒；新增的延迟加载等待已消除，整体改进温和。三个样本及重复进程测试不构成电源冷启动的统计保证。最终新版侧栏和编辑器的 DOM 观察时刻分别为 935 / 1,003 / 947 ms，三轮均在同一个观察周期出现。

本轮初始 2,000 页合成测试的启动样本为 1,057 毫秒，早期重构样本为 1,048 毫秒；输入观测样本为 348 和 385 毫秒。这些数据不支持声称所有场景都有明显提速。首次拆分编辑器还暴露了约 337 毫秒的实际渲染等待；在改用已预载组件同步挂载后，三次真实工作区副本观察中，侧栏与编辑器分别在同一个观察周期出现，额外等待已消除。

作为代码结构参照，旧版主入口 JavaScript 文件为 2,778,107 字节；最终新版入口及其全部静态 JavaScript 依赖合计 715,504 字节、157 个源模块，构建报告中的 `eagerOptionalModules` 为空。入口静态依赖体积与整个原生页面启动所需代码量是不同指标：选中原生页面会额外预载编辑器。不能把静态依赖减少百分比当作启动时延减少百分比。

历史延迟加载减少了启动时 151 次历史文件读取和相应 JSON.parse；同机热缓存后端构造样本仍约 0.2 秒，未显示明显稳定收益。真实工作区仍有约 24 MB 的当前页缓存，完整快照读取、校验与传输继续占据主要启动成本。没有据此宣称所有硬件的电源冷启动或大型图片内存问题已经解决。

## 可复现验证

在 `Engine/` 运行：

```sh
npm run build
npm run test:media
node scripts/test.mjs tests/history-startup.test.ts tests/performance-state.test.ts
node --test tests/preload-flush.test.cjs tests/startup-hint.test.cjs
node --test tests/folder.test.cjs
MINI_NOTION_BACKGROUND_TEST=1 npx playwright test tests/media-startup.e2e.ts tests/startup-fast.e2e.ts
```

真实工作区基准必须指向独立副本：

```sh
MINI_NOTION_PROFILE_WORKSPACE=/absolute/path/to/isolated-clone \
MINI_NOTION_PROFILE_SAMPLES=3 node scripts/profile-startup.mjs

MINI_NOTION_PROFILE_WORKSPACE=/absolute/path/to/isolated-clone \
node scripts/profile-startup-breakdown.mjs
```

比较安装版时另设 `MINI_NOTION_PROFILE_EXECUTABLE` 为其 app 内可执行文件。重复新进程启动不等于清空操作系统缓存后的电源冷启动。

测试覆盖图片无效/超时、原始字节保留、草稿合并和失败重试、关闭等待全部编辑器、历史校验与修复、目录移动的撤销/重做及原文件字节、首页/CSV 分批展示、图片缩放、明暗主题、封面键盘定位、页面导航和编辑器实例保持。
